
A* SEARCH ::

============================================================
1. WHAT IS A* SEARCH?
============================================================

A* (A-Star) Search is an informed search algorithm used to find
a minimum-cost path from a start node to a goal node.

A* combines:

1. Cost already spent to reach a node
2. Estimated cost remaining to reach the goal

The main evaluation function is:

f(n) = g(n) + h(n)

Where:

g(n) = Actual cost from the start node to node n

h(n) = Estimated cost from node n to the goal

f(n) = Estimated total cost of a solution through node n


IMPORTANT:

A* chooses the node with the smallest f(n) value for expansion.


============================================================
2. WHY IS A* CALLED AN INFORMED SEARCH?
============================================================

A* is called an informed search algorithm because it uses
additional knowledge about the problem in the form of a
heuristic function h(n).

Uninformed search:
Does not use an estimate of the distance to the goal.

Informed search:
Uses heuristic information to guide the search toward the goal.

A* uses both:

g(n) = information about the past

h(n) = information about the future


============================================================
3. THREE IMPORTANT VALUES IN A*
============================================================

Every important node in A* can be associated with:

g(n)
h(n)
f(n)


g(n):

Actual path cost from the start node to the current node.

Example:

S → A → B

If:

S → A = 2
A → B = 3

Then:

g(B) = 2 + 3 = 5


h(n):

Estimated cost from the current node to the goal.

Example:

h(B) = 7

This means we estimate that approximately 7 more cost is
required to reach the goal from B.


f(n):

Estimated total cost through node n.

Formula:

f(n) = g(n) + h(n)

Example:

g(B) = 5
h(B) = 7

Therefore:

f(B) = 5 + 7
f(B) = 12


============================================================
4. BASIC IDEA OF A*
============================================================

A* repeatedly does the following:

1. Start from the initial node.
2. Calculate g(n), h(n), and f(n).
3. Put the node into the OPEN list.
4. Select the node with the smallest f(n).
5. Expand that node.
6. Generate its successors/neighbors.
7. Calculate their g, h, and f values.
8. Add/update them in OPEN.
9. Move expanded nodes to CLOSED.
10. Repeat until the goal is selected for expansion.


IMPORTANT:

A* normally selects the node with the minimum:

f(n) = g(n) + h(n)


============================================================
5. OPEN LIST
============================================================

The OPEN list contains nodes that have been generated but
have not yet been expanded.

It can also be thought of as the frontier.

Example:

OPEN:

A
B
C
D

The node having the smallest f(n) is normally selected next.


============================================================
6. CLOSED LIST
============================================================

The CLOSED list contains nodes that have already been expanded.

Example:

CLOSED:

S
A
B

This means S, A, and B have already been processed/expanded.


============================================================
7. OPEN VS CLOSED
============================================================

OPEN LIST:

Contains nodes waiting to be expanded.

CLOSED LIST:

Contains nodes that have already been expanded.


Easy way to remember:

OPEN = "Waiting"

CLOSED = "Already processed"


============================================================
8. NODE EXPANSION
============================================================

Expanding a node means:

Taking the selected node and generating its neighboring
or successor nodes.

Example:

       A
      / \
     B   C

If A is expanded:

B and C are generated.


============================================================
9. GOAL TEST
============================================================

The goal test checks whether the selected node is the goal.

A common A* procedure is:

If the selected node is the goal,
stop and return the solution path.

Otherwise:

Continue expanding nodes.


IMPORTANT:

The goal should generally be accepted when it is selected
for expansion/removal from OPEN, not merely when it is first
generated, for standard optimal A* behavior.


============================================================
10. HEURISTIC FUNCTION
============================================================

A heuristic function estimates the cost from the current
node to the goal.

It is represented as:

h(n)

Example:

If:

h(A) = 8

Then the estimated cost from A to the goal is 8.


============================================================
11. TRUE COST VS HEURISTIC COST
============================================================

Actual remaining cost:

h*(n)

Heuristic estimate:

h(n)


h*(n) = Actual optimal cost from n to goal

h(n) = Estimated cost from n to goal


A good heuristic should give useful information about the
remaining cost without overestimating when optimality is required.


============================================================
12. ADMISSIBLE HEURISTIC
============================================================

A heuristic is admissible if it never overestimates the actual
minimum cost from a node to a goal.

Formula:

0 <= h(n) <= h*(n)

Where:

h(n) = heuristic estimate

h*(n) = true optimal remaining cost


Example:

True remaining cost = 10

Heuristic = 7

Admissible? YES

Because:

7 <= 10


Example:

True remaining cost = 10

Heuristic = 12

Admissible? NO

Because:

12 > 10


IMPORTANT:

Admissible means:

"Never overestimate."


============================================================
13. WHY IS ADMISSIBILITY IMPORTANT?
============================================================

If the heuristic is admissible, A* tree search can find an
optimal solution under the standard assumptions.

The reason is that the heuristic gives a lower bound on the
remaining cost.

Therefore:

f(n) = g(n) + h(n)

does not overestimate the actual cost of the best solution
through n.

============================================================
14. CONSISTENT HEURISTIC
============================================================

A heuristic is consistent if, for every edge from n to n':

h(n) <= c(n,n') + h(n')

Where:

c(n,n') = cost of moving from n to n'

This is also called the triangle inequality condition.


Simple meaning:

The estimated cost from the current node should not be greater
than the cost of taking one step to a neighboring node plus the
neighbor's estimated cost to the goal.


============================================================
15. CONSISTENCY EXAMPLE
============================================================

Suppose:

h(A) = 8

Edge cost:

A → B = 3

h(B) = 5

Check:

h(A) <= cost(A,B) + h(B)

8 <= 3 + 5

8 <= 8

Therefore:

The heuristic is consistent for this edge.


============================================================
16. INCONSISTENT HEURISTIC EXAMPLE
============================================================

Suppose:

h(A) = 10

A → B cost = 3

h(B) = 5

Check:

10 <= 3 + 5

10 <= 8

FALSE

Therefore:

The heuristic is NOT consistent.


============================================================
17. ADMISSIBLE VS CONSISTENT
============================================================

ADMISSIBLE:

Never overestimates the true remaining cost.

CONSISTENT:

Satisfies:

h(n) <= c(n,n') + h(n')

for every edge.


IMPORTANT:

Consistency is stronger than admissibility.

Every consistent heuristic is admissible.

But an admissible heuristic is not necessarily consistent.


============================================================
18. IMPORTANT RELATIONSHIP
============================================================

Consistent
   ↓
Admissible

But:

Admissible
   X
does NOT always imply
Consistent


============================================================
19. HEURISTIC AT THE GOAL
============================================================

For a standard admissible heuristic:

h(goal) = 0

Why?

Because the cost from the goal to itself is zero.


============================================================
20. EXAMPLE OF A* CALCULATION
============================================================

Suppose:

g(A) = 4
h(A) = 6

Then:

f(A) = g(A) + h(A)

f(A) = 4 + 6

f(A) = 10


============================================================
21. SIMPLE A* GRAPH
============================================================

Consider:

        2
   S -------- A
   |          |
  5|          |3
   |          |
   B -------- G
        4


Edges:

S → A = 2
S → B = 5
A → G = 3
B → G = 4

Heuristic values:

h(S) = 5
h(A) = 3
h(B) = 4
h(G) = 0


Calculate:

For S:

g(S) = 0
h(S) = 5

f(S) = 0 + 5 = 5


For A:

g(A) = 2
h(A) = 3

f(A) = 2 + 3 = 5


For B:

g(B) = 5
h(B) = 4

f(B) = 5 + 4 = 9


A* chooses:

A

because:

f(A) = 5
f(B) = 9


Expand A.

Then G:

g(G) = 2 + 3 = 5

h(G) = 0

f(G) = 5


Goal is selected.

Optimal path:

S → A → G

Total cost:

2 + 3 = 5


============================================================
22. STEP-BY-STEP A* SIMULATION
============================================================

General format:

Step 1:

OPEN = {Start}

CLOSED = { }


Step 2:

Select node with minimum f(n).


Step 3:

Move selected node to CLOSED.


Step 4:

Generate its neighbors.


Step 5:

Calculate:

g(n)
h(n)
f(n)


Step 6:

Add/update neighbors in OPEN.


Step 7:

Again select minimum f(n).


Step 8:

Repeat until goal is selected.


============================================================
23. IMPORTANT A* RULE
============================================================

When multiple nodes are available:

Choose the node with the smallest f(n).

Remember:

f(n) = g(n) + h(n)


============================================================
24. TIE IN A*
============================================================

Sometimes two or more nodes have the same f(n).

Example:

f(A) = 10
f(B) = 10

There is a tie.

A tie-breaking rule may be used.

Possible choices:

- Smaller h(n)
- Larger g(n)
- Earlier generated node
- Any specified rule in the question

IMPORTANT:

If the exam specifies a tie-breaking rule,
follow that rule.

If no rule is specified, clearly state your chosen
tie-breaking rule.


============================================================
25. A* AND UNIFORM COST SEARCH
============================================================

Uniform Cost Search uses:

f(n) = g(n)

A* uses:

f(n) = g(n) + h(n)


Therefore:

UCS ignores heuristic information.

A* uses heuristic information.


============================================================
26. A* AND GREEDY BEST-FIRST SEARCH
============================================================

Greedy Best-First Search uses:

f(n) = h(n)

A* uses:

f(n) = g(n) + h(n)


Greedy:

Only considers estimated distance to goal.

A*:

Considers both actual cost and estimated remaining cost.


============================================================
27. BFS VS UCS VS GREEDY VS A*
============================================================

BFS:

Priority based mainly on depth.

UCS:

f(n) = g(n)

Greedy Best-First:

f(n) = h(n)

A*:

f(n) = g(n) + h(n)


Easy memory trick:

BFS = Depth

UCS = Past Cost

Greedy = Future Estimate

A* = Past Cost + Future Estimate


============================================================
28. A* VS GREEDY BEST-FIRST SEARCH
============================================================

Greedy:

f(n) = h(n)

It may choose a node that appears close to the goal even if
the path taken so far is very expensive.

A*:

f(n) = g(n) + h(n)

It considers both the cost already spent and the estimated
remaining cost.

Therefore, A* generally makes a more balanced decision.


============================================================
29. A* VS UCS
============================================================

UCS:

f(n) = g(n)

A*:

f(n) = g(n) + h(n)


If:

h(n) = 0

Then:

f(n) = g(n)

Therefore:

A* becomes equivalent to Uniform Cost Search.


============================================================
30. PERFECT HEURISTIC
============================================================

A perfect heuristic gives the exact remaining cost:

h(n) = h*(n)

Then:

f(n) = g(n) + h*(n)

This gives exact information about the total cost through n.


============================================================
31. EFFECT OF h(n)
============================================================

If h(n) is:

1. Zero:
A* behaves like UCS.

2. Admissible but weak:
A* remains optimal but may explore many nodes.

3. Admissible and strong:
A* usually explores fewer unnecessary nodes.

4. Perfect:
A* has exact remaining-cost information.

5. Overestimating:
A* may lose optimality.


============================================================
32. HEURISTIC QUALITY
============================================================

A heuristic is generally considered better when it provides
more useful information while remaining admissible.

For two admissible heuristics h1 and h2:

If:

h1(n) <= h2(n) <= h*(n)

then h2 is usually considered more informed than h1.


============================================================
33. DOMINANCE BETWEEN HEURISTICS
============================================================

If two heuristics are admissible and:

h2(n) >= h1(n)

for every node n,

then h2 dominates h1.

A dominating admissible heuristic is generally more informed
and can reduce unnecessary node expansions.


============================================================
34. COMMON HEURISTICS
============================================================

Different problems require different heuristics.

Examples:

1. Manhattan Distance
2. Euclidean / Straight-Line Distance
3. Chebyshev Distance
4. Hamming Distance


============================================================
35. MANHATTAN DISTANCE
============================================================

Manhattan Distance is commonly used when movement is restricted
to four directions:

Up
Down
Left
Right


Formula:

Manhattan Distance =
|x1 - x2| + |y1 - y2|


Example:

Current = (2,3)
Goal = (5,7)

Distance:

|2 - 5| + |3 - 7|

= 3 + 4

= 7


============================================================
36. EUCLIDEAN DISTANCE
============================================================

Euclidean distance represents straight-line distance.

Formula:

d = sqrt((x1-x2)^2 + (y1-y2)^2)


Example:

Current = (1,1)
Goal = (4,5)

d = sqrt((1-4)^2 + (1-5)^2)

d = sqrt(9 + 16)

d = sqrt(25)

d = 5


============================================================
37. CHEBYSHEV DISTANCE
============================================================

Chebyshev distance is commonly used when diagonal movement
is allowed with the same cost as horizontal/vertical movement.

Formula:

d = max(|x1-x2|, |y1-y2|)


Example:

Current = (2,3)
Goal = (5,7)

d = max(3,4)

d = 4


============================================================
38. HAMMING DISTANCE
============================================================

Hamming distance measures the number of positions where two
states differ.

Example:

State 1:

1 2 3 4

State 2:

1 3 2 4

Differences:

Position 2
Position 3

Therefore:

Hamming Distance = 2


============================================================
39. HEURISTIC SELECTION
============================================================

The heuristic depends on the problem.

Grid with only up/down/left/right:

Use Manhattan Distance.

Grid where diagonal movement is allowed:

Chebyshev or another suitable diagonal-distance heuristic
may be used depending on movement costs.

Physical map:

Straight-line/Euclidean distance can be useful.


============================================================
40. WHY STRAIGHT-LINE DISTANCE CAN BE ADMISSIBLE
============================================================

Suppose a road network is used.

Straight-line distance represents the direct geometric distance.

A real road route normally cannot be shorter than the direct
straight-line distance between two locations.

Therefore:

Straight-line distance can be used as an admissible heuristic
for many road-routing problems.


============================================================
41. HEURISTIC OVERESTIMATION
============================================================

Suppose:

True remaining cost = 10

Heuristic = 15

Since:

15 > 10

The heuristic overestimates the actual cost.

Therefore:

It is NOT admissible.

An overestimating heuristic can cause A* to return a
non-optimal solution.

============================================================

Given:

        2
    S ------ A
    |        |
   4|        |5
    |        |
    B ------ G
        3

Heuristics:

h(S) = 5
h(A) = 5
h(B) = 3
h(G) = 0


Edges:

S-A = 2
S-B = 4
A-G = 5
B-G = 3


Step 1:

Start:

S

g(S) = 0
h(S) = 5
f(S) = 5


Expand S.


Generate A:

g(A) = 2
h(A) = 5
f(A) = 7


Generate B:

g(B) = 4
h(B) = 3
f(B) = 7


Now:

OPEN:

A: f=7

g(G) = 2 + 5

New path cost:

Same cost.

Optimal Path:

S → A → G

or

S → B → G

Both have cost:

7

43. ANOTHER A* SIMULATION
============================================================

Given:

S → A = 1
S → B = 4
A → C = 2
B → C = 1
C → G = 5

Heuristics:

h(S) = 5
h(A) = 5
h(B) = 3
h(C) = 5
h(G) = 0


Start:

S

g(S)=0
h(S)=5
f(S)=5


Expand S.

A:

g(A)=1
h(A)=5
f(A)=6


B:

g(B)=4
h(B)=3
f(B)=7


Choose A because:

6 < 7


Expand A.

C:

g(C)=1+2=3
h(C)=5
f(C)=8


OPEN:

B = 7
C = 8


Choose B.


Expand B.

New path to C:

g(C)=4+1=5

Existing g(C)=3

Since:

3 < 5

Keep the better path:

g(C)=3


Then:

f(C)=3+5=8


Expand C.

Generate G:

g(G)=3+5=8
h(G)=0
f(G)=8


Goal selected.

Optimal path:

S → A → C → G

Total cost:

1 + 2 + 5 = 8


============================================================
44. IMPORTANT PATH UPDATE RULE
============================================================

Suppose a node is already in OPEN.

Then a better path to that same node is discovered.

Example:

Existing:

g(C) = 10

New:

g(C) = 7

Since:

7 < 10

Update:

g(C) = 7

Then recalculate:

f(C) = g(C) + h(C)


IMPORTANT:

A* should keep the lower-cost path.


============================================================
45. WHAT IF A NODE IS REACHED THROUGH TWO PATHS?
============================================================

Example:

Path 1:

S → A → C

Cost = 10


Path 2:

S → B → C

Cost = 7


Choose:

Path 2

because:

g(C) = 7 < 10


============================================================
46. A* AND PATH COST
============================================================

A* does NOT choose a node simply because its g(n) is smallest.

It chooses according to:

f(n) = g(n) + h(n)


Example:

Node A:

g(A)=2
h(A)=10
f(A)=12


Node B:

g(B)=5
h(B)=2
f(B)=7


A* chooses B.

Even though:

g(A) < g(B)

because:

f(B) < f(A)


============================================================
47. A* AND HEURISTIC
============================================================

A* does NOT choose only the smallest h(n).

Example:

A:

g(A)=100
h(A)=1

f(A)=101


B:

g(B)=5
h(B)=10

f(B)=15


A* chooses B.

Because:

15 < 101


============================================================
48. OPTIMALITY OF A*
============================================================

A* can guarantee an optimal solution when its heuristic
satisfies the required conditions.

For A* tree search:

Admissible heuristic is sufficient under standard conditions.

For graph search:

Consistency is the standard stronger condition that ensures
the required optimality behavior without problematic reopening
of already-expanded nodes.


============================================================
49. COMPLETENESS OF A*
============================================================

Completeness means:

If a solution exists, the algorithm will eventually find one,
under the usual assumptions such as finite branching and
suitable positive/non-zero step costs.

For finite graphs with non-negative edge weights, A* terminates
and is complete.


============================================================
50. OPTIMALITY VS COMPLETENESS
============================================================

Completeness:

Will the algorithm find a solution if one exists?


Optimality:

Will the algorithm find the best/least-cost solution?


IMPORTANT:

These are different concepts.


============================================================
51. A* TIME COMPLEXITY
============================================================

A* can have exponential worst-case time complexity.

Its practical performance depends heavily on:

- Heuristic quality
- Branching factor
- Search depth
- Number of states
- Edge costs
- Problem structure


============================================================
52. A* SPACE COMPLEXITY
============================================================

A* can require large amounts of memory because it stores
many generated nodes in OPEN and often CLOSED.

Therefore, A* can be memory-intensive.


============================================================
53. WHY A* CAN BE SLOW
============================================================

A* may explore many nodes when:

- The heuristic is weak.
- The heuristic is close to zero.
- The search space is huge.
- Many nodes have similar f values.
- The heuristic provides little useful direction.


============================================================
54. WHY A* IS BETTER THAN UCS IN MANY CASES
============================================================

UCS only considers:

g(n)

A* considers:

g(n) + h(n)

Therefore, A* can use knowledge about where the goal is
to guide the search.

This can reduce unnecessary exploration.


============================================================
55. WHY A* IS BETTER THAN GREEDY IN TERMS OF COST
============================================================

Greedy uses:

h(n)

It ignores the cost already spent.

A* uses:

g(n) + h(n)

Therefore, A* balances:

Cost already spent
+
Estimated remaining cost


============================================================
56. SPECIAL CASES
============================================================

If:

h(n) = 0

Then:

f(n) = g(n)

Therefore:

A* = Uniform Cost Search


If:

g(n) is ignored

Then:

f(n) = h(n)

This becomes:

Greedy Best-First Search


============================================================
57. IMPORTANT A* TERMINOLOGY
============================================================

Start Node:

Initial state of the problem.


Goal Node:

Desired final state.


Successor:

A node reachable from the current node.


Edge Cost:

Cost of moving from one node to another.


Path Cost:

Total cost of all edges along a path.


Heuristic:

Estimated remaining cost to the goal.


OPEN:

Nodes waiting to be expanded.


CLOSED:

Nodes already expanded.


Evaluation Function:

f(n) = g(n) + h(n)


============================================================
58. COMMON MISTAKES IN A* SIMULATION
============================================================

Mistake 1:

Using only h(n).

Wrong.

A* uses:

f(n) = g(n) + h(n)


Mistake 2:

Using only g(n).

That is UCS.

Mistake 3:

Forgetting to update g(n) when a cheaper path is found.


Mistake 4:

Choosing the goal immediately when it is generated without
checking the remaining OPEN nodes in standard A*.


Mistake 5:

Incorrectly calculating cumulative g(n).


Mistake 6:

Using the wrong heuristic.


Mistake 7:

Ignoring the tie-breaking rule.


Mistake 8:

Confusing admissible and consistent.

64. SHORT CONCEPTUAL QUESTIONS
============================================================


Q1. What is A* Search?

A* is an informed search algorithm that finds a minimum-cost
path by using both actual path cost and estimated remaining cost.


Q2. Why is A* called an informed search?

Because it uses heuristic information to guide the search toward
the goal.


Q3. What is the evaluation function of A*?

f(n)=g(n)+h(n)


Q4. What is g(n)?

g(n) is the actual cost from the start node to node n.


Q5. What is h(n)?

h(n) is the estimated cost from node n to the goal.


Q6. What is f(n)?

f(n) is the estimated total cost of a solution through node n.

f(n)=g(n)+h(n)


Q7. What is a heuristic?

A heuristic is an estimate of the cost from a current node to
a goal node.


Q8. What is an admissible heuristic?

An admissible heuristic never overestimates the true minimum
remaining cost.

h(n) <= h*(n)


Q9. What is a consistent heuristic?

A heuristic is consistent if:

h(n) <= c(n,n') + h(n')

for every edge from n to n'.


Q10. What is the difference between admissible and consistent?

Admissibility means the heuristic never overestimates the true
remaining cost.

Consistency additionally requires the triangle inequality across
every edge.

Consistency is stronger than admissibility.


Q11. Is every consistent heuristic admissible?

Yes.


Q12. Is every admissible heuristic consistent?

No.


Q13. What is the OPEN list?

The OPEN list contains generated nodes that are waiting to be
expanded.


Q14. What is the CLOSED list?

The CLOSED list contains nodes that have already been expanded.


Q15. What is node expansion?

Node expansion means generating the successors/neighbors of a
selected node.


Q16. Which node does A* select?

A* normally selects the node with the smallest f(n).


Q17. What happens when h(n)=0?

A* becomes equivalent to Uniform Cost Search.


Q18. What function does UCS use?

UCS uses:

f(n)=g(n)


Q19. What function does Greedy Best-First Search use?

Greedy Best-First Search uses:

f(n)=h(n)


Q20. What function does A* use?

A* uses:

f(n)=g(n)+h(n)


Q21. What is a perfect heuristic?

A perfect heuristic gives the exact remaining cost:

h(n)=h*(n)


Q22. What happens if a heuristic overestimates?

The heuristic is not admissible, and A* may return a
non-optimal solution.


Q23. What is Manhattan Distance?

Manhattan Distance is the sum of the absolute differences
between coordinates.

Formula:

|x1-x2| + |y1-y2|


Q24. When is Manhattan Distance commonly used?

It is commonly used for grid problems where movement is limited
to four directions.


Q25. What is Euclidean Distance?

Euclidean Distance is the straight-line distance between two
points.

Formula:

sqrt((x1-x2)^2 + (y1-y2)^2)


Q26. What is Chebyshev Distance?

Chebyshev Distance is:

max(|x1-x2|, |y1-y2|)

It is commonly useful for grids where diagonal movement is
allowed with equal cost.


Q27. What is Hamming Distance?

Hamming Distance counts the number of positions at which two
states differ.


Q28. What is completeness?

Completeness means an algorithm will find a solution if one
exists under the required assumptions.


Q29. What is optimality?

Optimality means the algorithm returns the best or least-cost
solution.


Q30. Why is A* memory intensive?

Because A* stores generated nodes in structures such as OPEN
and CLOSED.


Q31. What is the main advantage of A*?

It combines actual path cost with heuristic information to
guide the search efficiently toward the goal.


Q32. What is the main disadvantage of A*?

It can require large amounts of time and memory for large
search spaces.


Q33. Why is heuristic quality important?

A good heuristic can guide A* toward promising nodes and reduce
unnecessary exploration.


Q34. What is heuristic dominance?

If two admissible heuristics satisfy:

h2(n) >= h1(n)

for every node, then h2 is said to dominate h1.


Q35. What happens if h(n)=h*(n)?

The heuristic is perfect because it exactly estimates the
remaining optimal cost.
